# Web app manifest — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Umbraco backoffice declares a web app manifest, so installing or pinning it gives a
named, correctly-iconed, chromeless window that opens on the desktop — with the icon a site-wide
setting rather than something the package decides for everybody.

**Architecture:** A C# endpoint serves the manifest anonymously; the backoffice bundle appends
`<link rel="manifest">` to `document.head` at runtime (measured to work in Chrome 153, Edge 153 and
Firefox 155 — see the spike). The icon resolves through appsettings, then Umbraco's key-value store,
then a shipped default, and is edited in a new gated **Site** category in desktop settings.

**Tech Stack:** .NET 10 / Umbraco 17 (`IKeyValueService`, `IOptions`, management API controllers,
xunit + NSubstitute), TypeScript + Lit for the backoffice, `sharp` for icon renders,
web-test-runner for the client tests.

**Design doc:** [`2026-09-13-web-app-manifest-design.md`](./2026-09-13-web-app-manifest-design.md).
Read §2 and §4 before starting. **Spike:**
[`spikes/2026-09-13-manifest-injection/`](./spikes/2026-09-13-manifest-injection/).

## Before you start: the artwork already exists, and is the weakest part

**Task 2 is done.** `backoffice/appicons-src/` holds both marks, the render script and a contact-sheet
tool, and `npm run appicons` produces all four PNGs. Task 2 below is kept as a record of what was
built and why, not as work to do.

**It was drawn by Claude, and it shows.** It is structurally correct — it survives the maskable
crop with room to spare, it reads at 32px, and it says "windowed desktop" rather than "some app".
It is also a competent-generic app tile: gradient, rounded square, white window. There is no idea in
it that a designer would have had. If the mark matters to you, replace it; nothing downstream knows
what it looks like, so that is one commit replacing two SVGs and re-running the build.

## APIs checked, not assumed

Every Umbraco type below was read out of `Umbraco.Core.xml` / `Umbraco.Web.Common.xml` in the 17.6.2
packages before this plan was written, because two plausible guesses turned out to be wrong:

| Need | Use | Not |
| --- | --- | --- |
| Backoffice virtual path | `IBackOfficePathGenerator.BackOfficePath` (`Umbraco.Cms.Web.Common.Hosting`) | `GlobalSettings.UmbracoPath` — **does not exist in Umbraco 17** |
| Site name | `IHostingEnvironment.SiteName` (`Umbraco.Cms.Core.Hosting`) | `GlobalSettings.SiteName` — does not exist either |
| Stored setting | `IKeyValueService.GetValue(string)` / `SetValue(string, string)` | — |

`IBackOfficePathGenerator` is what core's own `AllManifestController` takes for the same question,
which is about as strong a signal as the codebase gives.

The one thing in this plan **not** verified this way is the media thumbnail URL in Task 10. It is
flagged there.

## Two things that will bite

**Regenerating the API client needs a running site.** Task 9 adds a management API endpoint, and the
TypeScript client for it is generated by `npm run generate-client`, which reads
`https://localhost:44356/umbraco/swagger/management/swagger.json`. The TestInstance must be running
first. There is no offline path.

**The route segment must stay `umbradesktop`, no hyphen.** `backoffice/scripts/generate-openapi.js`
filters the spec on the path prefix `/umbraco/management/api/v1/umbradesktop`. A mismatch silently
produces an *empty* client rather than an error. This is already documented on
`BackgroundJobsController`.

```csharp
/// Exercises <see cref="WebAppManifestBuilder"/>, which is the only place manifest paths are
/// derived. Every case here is a path the package would otherwise get wrong on a site that has
/// moved its backoffice, which is configurable and therefore never safe to assume.
/// </summary>
public class WebAppManifestBuilderTests
{
    /// <summary>The icon set every test uses; its contents are irrelevant to path derivation.</summary>
    private static readonly IReadOnlyList<WebAppManifestIcon> Icons =

        new("/App_Plugins/Umbraco.Community.UmbraDesktop/appicons/icon-192.png", "192x192", "image/png", null),

    /// <summary>Builds with the default backoffice path, so the common case is pinned.</summary>
    [Fact]
    public void Builds_the_default_backoffice_paths()
    {
        var manifest = new WebAppManifestBuilder().Build("/umbraco", "Contoso", Icons);

        Assert.Equal("/umbraco/umbradesktop", manifest.Id);
        Assert.Equal("/umbraco/section/umbradesktop", manifest.StartUrl);
        Assert.Equal("/umbraco/", manifest.Scope);

    /// A configured backoffice path must flow through every derived path. This is the case that
    /// makes the builder worth existing rather than inlining the strings in the controller.
    /// </summary>
    [Fact]
    public void Honours_a_configured_backoffice_path()
    {
        var manifest = new WebAppManifestBuilder().Build("/manage", "Contoso", Icons);

        Assert.Equal("/manage/umbradesktop", manifest.Id);
        Assert.Equal("/manage/section/umbradesktop", manifest.StartUrl);
        Assert.Equal("/manage/", manifest.Scope);
    }

    /// <summary>
    /// A trailing slash must not double up. Umbraco's own base href carries one
    /// (<c>&lt;base href="/umbraco/" /&gt;</c>), so this is the shape the value actually arrives in.
    /// </summary>
    [Fact]
    public void Normalises_a_trailing_slash()
    {
        var manifest = new WebAppManifestBuilder().Build("/umbraco/", "Contoso", Icons);

        Assert.Equal("/umbraco/section/umbradesktop", manifest.StartUrl);
        Assert.Equal("/umbraco/", manifest.Scope);

    /// Scope must always end in a slash. Without it a sibling path that merely starts the same —

    /// </summary>
    [Fact]
    public void Scope_always_ends_in_a_slash()

        Assert.EndsWith("/", new WebAppManifestBuilder().Build("/manage", "X", Icons).Scope);
        Assert.EndsWith("/", new WebAppManifestBuilder().Build("/manage/", "X", Icons).Scope);

    /// <summary>Display must be standalone; it is the member the whole feature exists for.</summary>
    [Fact]
    public void Is_standalone()

        Assert.Equal("standalone", new WebAppManifestBuilder().Build("/umbraco", "X", Icons).Display);

    /// <summary>
    /// The site name becomes both names. <c>short_name</c> is what a taskbar shows when space is
```

```csharp
using System.Text.Json.Serialization;

namespace Umbraco.Community.UmbraDesktop.Manifest;

/// <summary>
/// One entry in a manifest's <c>icons</c> array.
/// </summary>
/// <param name="Src">Absolute path to the image.</param>
/// <param name="Sizes">The <c>WxH</c> size string, or <c>any</c> for a vector.</param>
/// <param name="Type">The image's media type.</param>
/// <param name="Purpose">
/// <c>maskable</c> for the padded render, or null for an ordinary icon. Null rather than
/// <c>"any"</c> because an entry with no purpose already means any, and omitting the member keeps
/// the served JSON to what actually carries meaning.
/// </param>
public sealed record WebAppManifestIcon(
    [property: JsonPropertyName("src")] string Src,
    [property: JsonPropertyName("sizes")] string Sizes,
    [property: JsonPropertyName("type")] string Type,
    [property: JsonPropertyName("purpose")] string? Purpose);

/// <summary>
/// The served web app manifest.
/// </summary>
/// <remarks>
/// Property names are snake_case by explicit attribute rather than by a naming policy, because
/// this record is serialised by whatever options the host has configured and a policy set
/// elsewhere is a silent way to ship a manifest no browser understands.
/// </remarks>
/// <param name="Id">
/// The app's stable identity. Different ids are distinct applications even from the same URL, which
/// is what lets a site's own frontend PWA and its backoffice install side by side. Set explicitly
/// so a later change to <paramref name="StartUrl"/> updates the installed app rather than
/// orphaning it.
/// </param>
/// <param name="Name">Full name, shown in install dialogs.</param>
/// <param name="ShortName">Short name, shown where space is tight.</param>
/// <param name="StartUrl">Where the installed app opens: the desktop section.</param>
/// <param name="Scope">
/// Which URLs stay inside the installed window. The backoffice root, so leaving the desktop for
/// <c>/section/content</c> does not eject the user into a browser tab.
/// </param>
/// <param name="Display">Always <c>standalone</c>.</param>
/// <param name="BackgroundColor">Painted before the app renders.</param>
/// <param name="ThemeColor">The OS window chrome's colour.</param>
/// <param name="Icons">The icon set.</param>
public sealed record WebAppManifest(
    [property: JsonPropertyName("id")] string Id,
    [property: JsonPropertyName("name")] string Name,
    [property: JsonPropertyName("short_name")] string ShortName,
    [property: JsonPropertyName("start_url")] string StartUrl,
    [property: JsonPropertyName("scope")] string Scope,
    [property: JsonPropertyName("display")] string Display,
    [property: JsonPropertyName("background_color")] string BackgroundColor,
    [property: JsonPropertyName("theme_color")] string ThemeColor,
    [property: JsonPropertyName("icons")] IReadOnlyList<WebAppManifestIcon> Icons);
```

```csharp
namespace Umbraco.Community.UmbraDesktop.Manifest;

/// <summary>
/// Derives every manifest path from the backoffice path, in one place.
/// </summary>
/// <remarks>
/// Pure, and separate from the controller, for the same reason <c>boot-decision.ts</c> is pure on
/// the client: these are rules whose mistakes are silent. A wrong scope does not throw, it just
/// quietly ejects the user into a browser tab a week later.
/// </remarks>
public sealed class WebAppManifestBuilder : IWebAppManifestBuilder
{
    /// <summary>The section's URL segment. Must match <c>UMBRADESKTOP_SECTION_PATHNAME</c> on the client.</summary>
    private const string SectionPathname = "umbradesktop";

    /// <summary>
    /// Name used when the site has none, so a nameless site is still installable.
    /// </summary>
    /// <remarks>
    /// The name arrives from <c>IHostingEnvironment.SiteName</c>, which is not guaranteed to be
    /// set, and <c>name</c> is a required manifest member — so an empty one would cost
    /// installability rather than just looking untidy.
    /// </remarks>
    private const string FallbackName = "Umbraco";

    /// <summary>Umbraco blue, matching the desktop's default theme.</summary>
    private const string ThemeColour = "#3544B1";

    /// <inheritdoc />
    public WebAppManifest Build(string backofficePath, string? siteName, IReadOnlyList<WebAppManifestIcon> icons)
    {
        var root = TrimTrailingSlash(backofficePath);
        var name = string.IsNullOrWhiteSpace(siteName) ? FallbackName : siteName.Trim();

        return new WebAppManifest(
            Id: $"{root}/{SectionPathname}",
            Name: name,
            ShortName: ShortenName(name),
            StartUrl: $"{root}/section/{SectionPathname}",
            // Trailing slash restored deliberately: without it a sibling path that merely starts
            // the same — /umbraco-admin against a scope of /umbraco — falls inside the app.
            Scope: $"{root}/",
            Display: "standalone",
            BackgroundColor: ThemeColour,
            ThemeColor: ThemeColour,
            Icons: icons);
    }

    /// <summary>
    /// Strip one trailing slash, so <c>/umbraco</c> and <c>/umbraco/</c> are one path.
    /// </summary>
    /// <param name="path">The path to normalise.</param>
    /// <returns>The path without its trailing slash, never empty.</returns>
    private static string TrimTrailingSlash(string path) =>
        path.Length > 1 && path.EndsWith('/') ? path[..^1] : path;

    /// <summary>
    /// Cut a long site name down to something a taskbar can show.
    /// </summary>
    /// <remarks>
    /// Truncated at a word boundary rather than mid-word, because the alternative is the OS
    /// clipping it wherever its own pixel budget runs out — which lands mid-word and looks broken.
    /// </remarks>
    /// <param name="name">The full name.</param>
    /// <returns>The short name.</returns>
    private static string ShortenName(string name)
    {
        const int maxLength = 12;
        if (name.Length <= maxLength) return name;

        var firstWord = name.Split(' ')[0];
        return firstWord.Length <= maxLength ? firstWord : firstWord[..maxLength];
    }
}
```

- `package.json` — `appicons`, `appicons:sheet`, and both chained into `build` and `watch`
- `.gitignore` — the generated sheets

**What it renders:** `icon-192.png`, `icon-512.png`, `icon-512-maskable.png`, `apple-touch-icon.png`
(180, flattened onto the theme colour, because iOS renders transparency black).

**The design,** so a replacement keeps what works: the tile *is* the desktop. The gradient is the
wallpaper, two overlapping windows float on it, and a dock sits at the bottom. That last element is
what stops it being the generic window-manager icon every OS ships — and the front window carries a
pale left column, which is the backoffice's own tree panel, so the body is not an empty white slab.

**Two things a replacement must not break:**

- **The maskable file is a different drawing, not a re-export.** A mask keeps only a centred circle
  of radius 40% of the icon size — 204.8px on a 512. The ordinary mark does not fit inside it, so
  the maskable variant scales the same artwork to 74% and bleeds the background to all four corners
  with no rounding, because the OS supplies the shape.
- **32px is the real test.** A taskbar button is about that size, and detail that reads beautifully
  at 512 turns to mush there.

**How to check a change:**

```bash
npm run appicons:sheet
```

Writes `sheet.png` and `sheet-maskable.png` into `appicons-src/`. Open them and look — the masked
sheet shows exactly what an Android launcher keeps, and the first draft of this icon looked fine at
512 while losing the whole left edge of its front window to the crop. An icon is a drawing and no
assertion can tell you it looks right.

```csharp
using Microsoft.AspNetCore.Authorization;
using Microsoft.AspNetCore.Mvc;
using Umbraco.Cms.Core.Hosting;
using Umbraco.Cms.Web.Common.Hosting;

namespace Umbraco.Community.UmbraDesktop.Manifest;

/// <summary>
/// Serves the backoffice's web app manifest.
/// </summary>
/// <remarks>
/// <para>
/// Routed at the site root rather than under the backoffice path, because everything under
/// <c>/umbraco</c> belongs to Umbraco's own routing and planting a route in it invites a collision
/// with a future core release. The manifest's own URL does not have to sit inside its
/// <c>scope</c>, so nothing is lost by being outside.
/// </para>
/// <para>
/// <see cref="AllowAnonymousAttribute"/> is load-bearing, not an oversight. The manifest is fetched
/// by the browser's install machinery rather than by the page, so it cannot be assumed to carry the
/// backoffice session, and an install can begin from the login screen. That bounds what may ever be
/// put in here to things that are already public.
/// </para>
/// </remarks>
/// <param name="builder">Derives the manifest's paths.</param>
/// <param name="pathGenerator">
/// Supplies the backoffice's virtual path. This, and not <c>GlobalSettings</c>: Umbraco 17 has no
/// <c>GlobalSettings.UmbracoPath</c> at all, and <see cref="IBackOfficePathGenerator"/> is what
/// core's own manifest controllers take for the same question.
/// </param>
/// <param name="hostingEnvironment">Supplies the site's name.</param>
[ApiController]
[AllowAnonymous]
public sealed class WebAppManifestController(
    IWebAppManifestBuilder builder,
    IBackOfficePathGenerator pathGenerator,
    IHostingEnvironment hostingEnvironment) : ControllerBase
{
    /// <summary>Where the rendered PNGs are served from, matching <c>build-appicons.mjs</c>.</summary>
    private const string IconBase = "/App_Plugins/Umbraco.Community.UmbraDesktop/appicons";

    /// <summary>
    /// Gets the manifest.
    /// </summary>
    /// <returns>The manifest as <c>application/manifest+json</c>.</returns>
    [HttpGet("umbradesktop/manifest.webmanifest")]
    [Produces("application/manifest+json")]
    public IActionResult Get()
    {
        var manifest = builder.Build(
            pathGenerator.BackOfficePath,
            hostingEnvironment.SiteName,
            icons: DefaultIcons());

        // Content type set explicitly rather than left to content negotiation: Chrome rejects a
        // manifest served as application/json in some paths, and the failure is silent.
        return new JsonResult(manifest) { ContentType = "application/manifest+json" };
    }

    /// <summary>
    /// The shipped icon set.
    /// </summary>
    /// <remarks>
    /// Three entries, and the third is not a duplicate of the second: a maskable icon is a
    /// different drawing, padded so that the centred circle a mask leaves behind still contains the
    /// whole mark. Phase 2 replaces this with a resolved set.
    /// </remarks>
    /// <returns>The icons.</returns>
    private static IReadOnlyList<WebAppManifestIcon> DefaultIcons() =>
    [
        new($"{IconBase}/icon-192.png", "192x192", "image/png", null),
        new($"{IconBase}/icon-512.png", "512x512", "image/png", null),
        new($"{IconBase}/icon-512-maskable.png", "512x512", "image/png", "maskable"),
    ];
}
```

```typescript
/**
 * Putting `<link rel="manifest">` into the backoffice head.
 *
 * Umbraco 17 generates the backoffice HTML in C# and ships no `index.html` to extend, so the link
 * has to be appended at runtime. That this works at all was not assumed: it was measured, because
 * the widely repeated advice says it does not. Chrome 153, Edge 153 and Firefox 155 all honour a
 * link appended five seconds after load — see `docs/design/spikes/2026-09-13-manifest-injection/`.
 *
 * It is behaviour rather than specification, though, and nothing in the manifest spec promises
 * re-evaluation on link mutation. If a future browser regresses, the fallback is response-rewriting
 * middleware over the backoffice HTML, and the spike's `c.html` is the variant to reach for.
 */

/** Id stamped on our link, so a second call can recognise its own work. */
export const UMBRADESKTOP_MANIFEST_LINK_ID = 'umbradesktop-manifest';

/**
 * Where the manifest is served.
 *
 * A site-root path rather than one derived from the backoffice path, because the endpoint is routed
 * at the site root — everything under `/umbraco` belongs to Umbraco's own routing. The manifest's
 * URL does not have to sit inside its own `scope`, so nothing is lost. The paths *inside* the
 * manifest are still derived from the configured backoffice path, server-side.
 * @returns The manifest URL.
 */
export function manifestHref(): string {
  return '/umbradesktop/manifest.webmanifest';
}

/**
 * Add our manifest link, unless the document already has one.
 *
 * **A manifest link the host already declared is never replaced.** A site whose own frontend PWA
 * manifest somehow reaches this document has made a deliberate choice, and silently overriding it
 * would take an installed app away from someone to give them ours. Ours is the one that yields.
 * @param head The head to add to. Injectable so the tests need no real document.
 */
export function upsertManifestLink(head: HTMLHeadElement = document.head): void {
  if (head.querySelector('link[rel="manifest"]')) return;

  const link = document.createElement('link');
  link.id = UMBRADESKTOP_MANIFEST_LINK_ID;
  link.rel = 'manifest';
  link.href = manifestHref();
  head.appendChild(link);
}
```

```csharp
    IKeyValueService keyValueService) : IAppIdentityResolver
{
    /// <summary>
    /// Key the backoffice-set values are stored under.
    /// </summary>
    /// <remarks>
    /// Prefixed with the package id because the key-value store is one flat namespace shared with
    /// core and every other package on the site.
    /// </remarks>
    public const string StorageKey = "Umbraco.Community.UmbraDesktop.AppIdentity";

    /// <summary>Enum names rather than numbers, so a stored document is readable and diffable.</summary>
    private static readonly JsonSerializerOptions StorageJson = new()
    {
        Converters = { new JsonStringEnumConverter() },
    };

    /// <inheritdoc />
    public AppIconSource ResolveIcon()
    {
        // Configuration first and unconditionally. Present means pinned, which is the point of
        // having it: it survives a database restore from another environment.
        if (options.Value.AppIcon is { } configured)
        {
            return Validate(new AppIconSource(configured.Mode, configured.MediaKey));
        }

        if (Stored()?.AppIcon is { } stored)
        {
            return Validate(new AppIconSource(stored.Mode, stored.MediaKey));
        }

        return AppIconSource.Default;
    }

    /// <inheritdoc />
    /// <remarks>
    /// The last step reads <see cref="HostingSettings.SiteName"/> from configuration rather than
    /// <c>IHostingEnvironment.SiteName</c>, and that is the entire reason this method is worth
    /// having. <c>IHostingEnvironment</c> has already substituted the <i>application</i> name by the
    /// time you see it, so a site that configured nothing is indistinguishable from one that
    /// deliberately chose an assembly identifier — and most sites configure nothing, which is how a
    /// taskbar ends up reading <c>Contoso.Web.Site</c>. Reading the options gives a real null, and
    /// null is something the caller can replace with a word a human would recognise.
    /// </remarks>
    public string? ResolveName()
    {
        // Same order as the icon, and blank is treated as absent at every step: clearing the field
        // means "stop overriding", not "call it nothing".
        if (NonBlank(options.Value.AppName) is { } configured) return configured;
        if (NonBlank(Stored()?.AppName) is { } stored) return stored;
        return NonBlank(hostingSettings.Value.SiteName);
    }

    /// <summary>
    /// Read and parse the stored document, tolerating anything unreadable.
    /// </summary>
    /// <remarks>
    /// Failure is swallowed rather than thrown. This runs inside an anonymous endpoint the browser
    /// hits unprompted, so an exception is a 500 on a URL nobody chose to visit — and the cost of a
    /// bad stored value should be the wrong name or picture, not a dead manifest.
    /// </remarks>
    /// <returns>The stored document, or null when absent or unreadable.</returns>
    private StoredAppIdentity? Stored()
    {
        var raw = keyValueService.GetValue(StorageKey);
        if (string.IsNullOrWhiteSpace(raw)) return null;

        try
        {
            return JsonSerializer.Deserialize<StoredAppIdentity>(raw, StorageJson);
        }
        catch (JsonException)
        {
            return null;
        }
    }

    /// <summary>
    /// Trim a value, treating blank as absent.
    /// </summary>
    /// <param name="value">The candidate.</param>
    /// <returns>The trimmed value, or null when it was null or whitespace.</returns>
    private static string? NonBlank(string? value) =>
        string.IsNullOrWhiteSpace(value) ? null : value.Trim();

    /// <summary>
    /// Reject a choice that cannot actually produce an icon.
    /// </summary>
    /// <remarks>
    /// Custom with no media is the only such case, and it matters more than it looks: a manifest
    /// with no usable icon is not installable at all, so this would take the feature down rather
    /// than merely showing the wrong mark.
    /// </remarks>
    /// <param name="source">The candidate.</param>
    /// <returns>The candidate, or the default when it cannot produce an icon.</returns>
    private static AppIconSource Validate(AppIconSource source) =>
        source is { Mode: AppIconMode.Custom, MediaKey: null } ? AppIconSource.Default : source;
}
```

```csharp
namespace Umbraco.Community.UmbraDesktop.Manifest;

/// <summary>
/// Builds the manifest's icon entries for each mode.
/// </summary>
public sealed class AppIconSetFactory : IAppIconSetFactory
{
    /// <summary>Where the rendered PNGs are served from, matching <c>build-appicons.mjs</c>.</summary>
    private const string IconBase = "/App_Plugins/Umbraco.Community.UmbraDesktop/appicons";

    /// <inheritdoc />
    public IReadOnlyList<WebAppManifestIcon> Create(AppIconSource source) => source.Mode switch
    {
        AppIconMode.Favicon =>
        [
            // "any" rather than a size, because nothing here can know what the site's favicon is,
            // and claiming a size a file does not have is worse than claiming none.
            new("/favicon.ico", "any", "image/x-icon", null),
        ],
        AppIconMode.Custom when source.MediaKey is { } key && MediaUrl(key) is { } mediaUrl =>
        [
            new(Resized(mediaUrl, 192), "192x192", "image/png", null),
            new(Resized(mediaUrl, 512), "512x512", "image/png", null),
        ],
        // Default; and Custom whose media is missing or since deleted, which the resolver should
        // already have turned into Default — belt and braces, because the alternative is an empty
        // icons array and a manifest that is not installable at all.
        _ =>
        [
            new($"{IconBase}/icon-192.png", "192x192", "image/png", null),
            new($"{IconBase}/icon-512.png", "512x512", "image/png", null),
            new($"{IconBase}/icon-512-maskable.png", "512x512", "image/png", "maskable"),
        ],
    };

    /// <summary>
    /// The media item's own URL, as Umbraco resolves it.
    /// </summary>
    /// <remarks>
    /// Asked for rather than assembled, and this matters even though no processing is involved yet:
    /// the media file system is an abstraction, and a site using Azure Blob Storage resolves media
    /// completely differently from one on local disk. A hand-built <c>/media/...</c> path is a
    /// local-disk assumption that breaks silently everywhere else.
    /// </remarks>
    /// <param name="key">The chosen media item.</param>
    /// <returns>The URL, or null when the item has gone.</returns>
    private string? MediaUrl(Guid key) => publishedUrlProvider.GetMediaUrl(key);

    /// <summary>
    /// One square render of a media URL, signed by Umbraco.
    /// </summary>
    /// <remarks>
    /// <c>Crop</c> so a non-square upload fills the tile rather than being letterboxed: an icon that
    /// does not fill its tile reads as broken, where a crop reads as a crop. No <c>Format</c> is
    /// requested — Umbraco picks a sensible output itself, and the fewer processing commands in the
    /// URL the less there is to get wrong.
    /// </remarks>
    /// <param name="mediaUrl">The media's own URL.</param>
    /// <param name="size">The square edge length in pixels.</param>
    /// <returns>The generated URL, falling back to the unprocessed one.</returns>
    private string Resized(string mediaUrl, int size) =>
        imageUrlGenerator.GetImageUrl(new ImageUrlGenerationOptions(mediaUrl)
        {
            Width = size,
            Height = size,
            ImageCropMode = ImageCropMode.Crop,
        }) ?? mediaUrl;
}
```

**The factory therefore takes two dependencies**, so it is no longer parameterless:
`IPublishedUrlProvider` to turn a media key into its URL, and `IImageUrlGenerator` to render that at
each size. Substitute both in `AppIconSetFactoryTests` — the URL provider returning
`/media/abc123/logo.png` for a fixed `MediaKey`, and the generator echoing
`$"{options.ImageUrl}?w={options.Width}"` so the *request* can be asserted without pinning a URL
shape that belongs to ImageSharp. The Default and Favicon assertions are unaffected.

**A media item that has been deleted resolves to null.** Treat that as Custom-with-no-media and fall
back to Default, for the same reason the resolver does: a manifest with an empty `icons` array is not
installable, so losing the picture must never cost the install.

> **Still verify it in a browser.** Open a generated icon URL while signed out. Anything other than
> the image means this is wrong, and the failure is invisible from inside an authenticated
> backoffice. An empty 400 specifically means the URL lost its signature somewhere — which is what
> hand-assembling one causes.
> The one case that will legitimately fail is media under public access restriction, which 403s
> anonymously — worth a line in `docs/app-icon.md` telling people to keep the icon somewhere public.

```csharp
using Microsoft.AspNetCore.Http;
using Microsoft.AspNetCore.Mvc;
using Microsoft.Extensions.Options;
using Umbraco.Cms.Api.Management.Controllers;
using Umbraco.Cms.Api.Management.Routing;

namespace Umbraco.Community.UmbraDesktop.Api;

/// <summary>
/// Reads and writes the site-wide app icon setting.
/// </summary>
/// <remarks>
/// <para>
/// The route segment must stay <c>umbradesktop</c> without a hyphen:
/// <c>backoffice/scripts/generate-openapi.js</c> filters the spec on the path prefix
/// <c>/umbraco/management/api/v1/umbradesktop</c>, and a mismatch silently produces an empty client.
/// </para>
/// <para>
/// Gated on Settings-section access, unlike everything else the desktop stores. This is the first
/// setting in that dialog that is not one user's preference: it changes the icon every person on
/// the site gets, so an editor adjusting their wallpaper must not be able to reach it.
/// </para>
/// </remarks>
/// <param name="resolver">Resolves the effective setting.</param>
/// <param name="keyValueService">Where the stored value lives.</param>
/// <param name="options">Used only to report whether configuration has taken the choice over.</param>
[ApiVersion("1.0")]
[VersionedApiBackOfficeRoute("umbradesktop/app-icon")]
[ApiExplorerSettings(GroupName = "UmbraDesktop")]
[Authorize(Policy = AuthorizationPolicies.SectionAccessSettings)]
public class AppIconController(
    IAppIdentityResolver resolver,
    IKeyValueService keyValueService,
    IOptions<UmbraDesktopOptions> options) : ManagementApiControllerBase
{
    /// <summary>Serialiser options, with the enum written as its name rather than its number.</summary>
    private static readonly JsonSerializerOptions StorageJson = new()
    {
        Converters = { new JsonStringEnumConverter() },
    };

    /// <summary>
    /// Gets the effective icon setting.
    /// </summary>
    /// <returns>The setting, and whether configuration has locked it.</returns>
    [HttpGet]
    [MapToApiVersion("1.0")]
    [ProducesResponseType(typeof(AppIconResponseModel), StatusCodes.Status200OK)]
    public IActionResult GetAppIcon()
    {
        var icon = resolver.ResolveIcon();

        return Ok(new AppIconResponseModel(
            icon.Mode,
            icon.MediaKey,
            LockedByConfiguration: options.Value.AppIcon is not null,
            Name: resolver.ResolveName(),
            NameLockedByConfiguration: options.Value.AppName is not null));
    }

    /// <summary>
    /// Stores a new icon setting.
    /// </summary>
    /// <param name="request">The setting to store.</param>
    /// <returns>No content on success, 400 for Custom with no media, 409 when configuration owns the value.</returns>
    [HttpPost]
    [MapToApiVersion("1.0")]
    [ProducesResponseType(StatusCodes.Status204NoContent)]
    [ProducesResponseType(StatusCodes.Status400BadRequest)]
    [ProducesResponseType(StatusCodes.Status409Conflict)]
    public IActionResult SetAppIcon(AppIconRequestModel request)
    {
        // Refused rather than silently stored. Writing a value that configuration will override on
        // every read would leave the user staring at an unchanged icon with no explanation.
        if (options.Value.AppIcon is not null)
        {
            return Conflict("The app icon is set in configuration and cannot be changed here.");
        }

        if (options.Value.AppName is not null && !string.IsNullOrWhiteSpace(request.Name))
        {
            return Conflict("The app name is set in configuration and cannot be changed here.");
        }

        if (request.Mode == AppIconMode.Custom && request.MediaKey is null)
        {
            return BadRequest("A custom app icon needs a media item.");
        }

        keyValueService.SetValue(
            AppIdentityResolver.StorageKey,
            JsonSerializer.Serialize(
                new StoredAppIdentity
                {
                    AppIcon = new AppIconOptions { Mode = request.Mode, MediaKey = request.MediaKey },
                    // Blank is stored as null rather than as "": clearing the field means "stop
                    // overriding and go back to the site's own name", not "name it nothing".
                    AppName = string.IsNullOrWhiteSpace(request.Name) ? null : request.Name.Trim(),
                },
                StorageJson));

        return NoContent();
    }
}
```

Create `backoffice/src/desktop/settings/categories/site/site.element.ts`:

```typescript
import { css, customElement, html, state } from '@umbraco-cms/backoffice/external/lit';
import { UmbLitElement } from '@umbraco-cms/backoffice/lit-element';
import { getAppIcon, setAppIcon } from '../../../../api/sdk.gen.js';

/** The three icon modes, matching the C# `AppIconMode` enum by name. */
type AppIconMode = 'Default' | 'Favicon' | 'Custom';

/**
 * Site-wide settings. The installed app's icon today.
 *
 * Unlike every other category, this reads and writes the server rather than the per-user settings
 * context: the value is one site's, not one person's, and it has to be readable by an anonymous
 * manifest request that no browser session is attached to.
 */
@customElement('umbradesktop-settings-site')
export class UmbraDesktopSettingsSiteElement extends UmbLitElement {
  /** The mode currently in force. */
  @state()
  private _mode: AppIconMode = 'Default';

  /** Whether appsettings.json owns the icon, in which case its controls are disabled. */
  @state()
  private _locked = false;

  /** The app's effective name, or null when nothing names this site. */
  @state()
  private _name: string | null = null;

  /** Whether appsettings.json owns the name. Tracked apart from the icon: the two pin separately. */
  @state()
  private _nameLocked = false;

  /** Whether the first load has finished, so the controls do not flash a wrong value first. */
  @state()
  private _loaded = false;

  override connectedCallback(): void {
    super.connectedCallback();
    void this.#load();
  }

  /** Read the current setting from the server. */
  async #load(): Promise<void> {
    const { data } = await getAppIcon();
    if (!data) return;
    this._mode = data.mode as AppIconMode;
    this._locked = data.lockedByConfiguration;
    this._name = data.name ?? null;
    this._nameLocked = data.nameLockedByConfiguration;
    this._loaded = true;
  }

  /**
   * Store a new mode, then re-read rather than trusting the write.
   *
   * Re-reading is not ceremony: the server refuses a write that configuration owns, and a UI that
   * assumed its own write landed would show a setting the manifest does not actually use.
   * @param mode The mode to store.
   */
  async #select(mode: AppIconMode): Promise<void> {
    if (this._locked) return;
    // The name rides along on every write. The stored document holds both, so posting an icon
    // without it would blank the name as a side effect of changing the picture.
    await setAppIcon({ body: { mode, mediaKey: null, name: this._name } });
    await this.#load();
  }

  /**
   * The icon picker, plus the sentence that explains why it might be disabled.
   * @returns The screen's contents.
   */
  override render() {
    if (!this._loaded) return html`<uui-loader></uui-loader>`;

    return html`
      <h4>${this.localize.term('umbraDesktop_siteAppIcon')}</h4>
      <p class="hint">${this.localize.term('umbraDesktop_siteAppIconAbout')}</p>

      <uui-radio-group
        .value=${this._mode}
        ?disabled=${this._locked}
        @change=${(event: Event) =>
          void this.#select((event.target as HTMLInputElement).value as AppIconMode)}>
        <uui-radio value="Default">${this.localize.term('umbraDesktop_siteAppIconDefault')}</uui-radio>
        <uui-radio value="Favicon">${this.localize.term('umbraDesktop_siteAppIconFavicon')}</uui-radio>
      </uui-radio-group>

      ${this._locked
        ? html`<p class="hint locked">${this.localize.term('umbraDesktop_siteAppIconLocked')}</p>`
        : null}

      <h4>${this.localize.term('umbraDesktop_siteAppName')}</h4>
      <p class="hint">${this.localize.term('umbraDesktop_siteAppNameAbout')}</p>

      <uui-input
        .value=${this._name ?? ''}
        ?disabled=${this._nameLocked}
        @change=${(event: Event) => void this.#saveName((event.target as HTMLInputElement).value)}>
      </uui-input>

      ${this._nameLocked
        ? html`<p class="hint locked">${this.localize.term('umbraDesktop_siteAppNameLocked')}</p>`
        : null}
    `;
  }

  static override styles = [
    css`
      :host {
        display: block;
      }
      h4 {
        margin: 0 0 var(--uui-size-space-2);
      }
      .hint {
        margin: 0 0 var(--uui-size-space-4);
        color: var(--uui-color-text-alt, var(--uui-color-text));
        font-size: var(--uui-type-small-size);
      }
      /* Sits under the disabled control it explains, not over it. */
      .locked {
        margin: var(--uui-size-space-3) 0 0;
      }
    `,
  ];
}

export default UmbraDesktopSettingsSiteElement;

declare global {
  interface HTMLElementTagNameMap {
    'umbradesktop-settings-site': UmbraDesktopSettingsSiteElement;
  }
}
```

```typescript
  /**
   * Store a new app name, then re-read.
   *
   * Fired on `change` rather than `input`: this writes to a site-wide setting, and saving on every
   * keystroke would be one request per character and a stored value that is briefly whatever a
   * half-typed name happens to be.
   *
   * An empty value is sent as-is and deliberately. The server stores blank as null, which means
   * "stop overriding" — clearing the field is how an admin goes back to the site's own name, so it
   * must not be swallowed here.
   * @param value The typed name.
   */
  async #saveName(value: string): Promise<void> {
    if (this._nameLocked) return;
    await setAppIcon({ body: { mode: this._mode, mediaKey: this._mediaKey, name: value } });
    await this.#load();
  }

  /**
   * Store a chosen media item.
   *
   * An empty selection is ignored rather than stored: the server refuses Custom with no media
   * (a manifest with no 192 and no 512 is not installable at all), so sending one would be a
   * guaranteed 400 the moment someone clears the picker mid-edit.
   * @param key The media key, or undefined when the picker was cleared.
   */
  async #selectMedia(key: string | undefined): Promise<void> {
    if (this._locked || !key) return;
    await setAppIcon({ body: { mode: 'Custom', mediaKey: key, name: this._name } });
    await this.#load();
```
