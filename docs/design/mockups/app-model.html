Each app = a backoffice URL + a "chrome profile" (full-section-with-tree · workspace-only · raw). That single idea covers both of your cases: Content brings its tree; your tools open bare. Apps also reuse Umbraco's condition system, so they hide when the user lacks permission — for free.

So — how are apps defined?

A

A manifest extension type — recommended

A new desktopApp extension any package registers via manifest. Your permissions editor & access viewer self-register. Third parties extend the desktop with one manifest. Plus auto-derive apps from existing section manifests, so Content/Media/etc. appear with zero config. Most Umbraco-idiomatic; maximises reuse.

B

A curated fixed list

The package ships a hardcoded set of apps + a config file where you list your custom ones (title, URL, icon). Simpler to build, but not extensible by others and nothing appears automatically.

I lean hard toward A — it's the difference between "a desktop for my two tools" and "a desktop platform any package can drop apps onto," for barely more effort. But tell me if that's over-engineering for what you want right now.
