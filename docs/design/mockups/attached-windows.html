Attached windows

Revised after the first build. Docked becomes a pane inside the document window; floating stays a separate window, gets its own taskbar button inside its owner's group, and its own minimize and maximize.

1. Docked: a pane inside the document window

One window, one border, so nothing can overlap. The pane runs from the titlebar down with its own header (title, reload, pop out, close) and a splitter; the path strip and any notices stay over the editor, because they are about the editor's content. The Preview button shows as pressed while the pane is open, and clicking it then closes the pane. Opening it widens the window so the editor keeps its width; when that does not fit on the desktop, the preview opens floating instead. No taskbar button: the pane is part of the window.

2. Floating, with the editor in front

A separate window, attached. The group rises as one, and inside it the window you focus goes on top, so the editor can cover the preview. The preview's own button, inside the owner's group box, brings it back. The link mark in its titlebar says it belongs to something.

3. Floating, with the preview in front

Clicking the preview's button, or the preview itself, puts it on top. The active marker moves to its button; the group box does not move. Clicking the active button again minimizes that window only; minimizing the editor would take the whole group.

4. Docking by dragging: the pointer decides

While a floating preview is dragged, bringing the pointer within reach of the owner's right edge shows the pane ghost inside the owner; letting go docks it. Where the window's own edge happens to be does not matter. Dragging a pane's header out of its window does the reverse and makes it float.

5. The three kinds of header

The owner keeps its titlebar exactly as it is. A floating attached window has a full set of controls now that it has its own taskbar button, plus the link mark. A pane has no minimize or maximize: it goes wherever its window goes.

6. The group box under three themes

The box is the signal, not the labels, so it survives the two icon-only themes. Each theme draws it in its own idiom through new tokens: a bordered box on Umbraco, a tray on the macOS dock, a sunken groove on Windows 98.

What changed since the first build

  • Docked is a pane inside the owner, not a second window beside it. The overlap goes, and so do all the rules for moving, clamping and maximizing a pair.
  • Floating windows get a taskbar button, inside their owner's group box, each clickable on its own.
  • Inside a group, the focused window is on top. The group still rises as one.
  • Floating windows get minimize and maximize, because their button can always bring them back. Minimizing the owner still takes the whole group.
  • Reload on the floating titlebar and in the pane header.
  • Docking follows the pointer, not the edge of the window being dragged.
